3. Benchmark context and metric meaning
--------------------------------------------------------------------------------------------------------------
The task is an active-learning simulation over a MOF synthesis candidate pool.
Each active-learning iteration proposes a batch of experiments.
The optimization objective is q_final, defined as Intensity_final divided by FWHM_final.
Higher q_final means stronger diffraction intensity and sharper peak width, so higher is better.

Metric meanings:
- best_q: This curve tracks the best q_final found up to each active-learning iteration. Higher values mean the method found better synthesis conditions. Direction rule: higher.
- simple_regret: This curve is pool_oracle_best_q minus the method's best q found so far. Lower values are better. Zero means the method found the best candidate in the pool. Direction rule: lower.
- normalized_regret: This is simple regret scaled by the q range. Lower values are better and easier to compare across datasets. Direction rule: lower.
- hit_top1pct: This curve reports the fraction of repeated runs whose best condition is in the top 1 percent of the candidate pool. Higher values are better. Direction rule: higher.
- hit_top0_1pct: This is a stricter rare-discovery curve. It reports the fraction of repeated runs whose best condition is in the top 0.1 percent of the candidate pool. Higher values are better. Direction rule: higher.
- surrogate_rmse_raw: This curve measures point-prediction error on held-out q_final values. Lower values mean better numerical prediction accuracy. Direction rule: lower.
- surrogate_mae_raw: This curve measures the typical absolute prediction error on held-out q_final values. Lower values are better. Direction rule: lower.
- surrogate_spearman_raw: This curve measures whether the surrogate ranks candidate conditions correctly. Higher values are better for screening and optimization. Direction rule: higher.
- surrogate_crps: CRPS evaluates probabilistic predictions. Lower values mean the predictive distribution is more accurate and better calibrated. Direction rule: lower.
- surrogate_nll: Negative log likelihood evaluates probabilistic predictions. Lower values are better, but very overconfident uncertainty can be punished strongly. Direction rule: lower.
- surrogate_coverage95: This curve measures how often held-out targets fall inside nominal 95 percent predictive intervals. The best value is close to 0.95, not simply the largest value. Direction rule: close_to_0.95.
- cum_seconds: This curve measures cumulative compute time for model fitting and acquisition. Lower values mean the method is faster. Direction rule: lower.
- mean_pairwise_batch_distance: This curve measures diversity among the proposed experiments within each batch. Higher values mean the batch suggestions are more spread out in scaled feature space. Direction rule: higher.

22. Suggested paper narrative skeleton
--------------------------------------------------------------------------------------------------------------
Paragraph 1. Define the active-learning benchmark.
State that the design grid contains MOF synthesis candidates parameterized by the synthesis variables, and the goal is to maximize q_final.

Paragraph 2. Explain why multiple method families were tested.
Mention classical BO, robust GP, approximate GP, tree ensembles, probabilistic ML, contextual bandits, and LLM-guided strategies when present.

Paragraph 3. Report optimization outcome.
Use final_best_q_mean, hit_top1pct_rate, hit_top0_1pct_rate, normalized regret, and the best-q curve.

Paragraph 4. Report early discovery, speed, and reliability.
Use highest-q-at-iteration, final quality vs runtime, AUC of best-q curve, and repeat-to-repeat stability.

Paragraph 5. Report surrogate quality.
Use RMSE, MAE, Spearman, CRPS, NLL, and 95 percent coverage to separate prediction quality from optimization success.

Paragraph 6. Report chemical patterns.
Discuss feature values and combinations repeatedly selected in high-q conditions as hypothesis generation.

Paragraph 7. Caveats.
Mention that the oracle is the best in the candidate pool, not necessarily the true wet-lab optimum.

23. Caveats and checks before writing the paper
--------------------------------------------------------------------------------------------------------------
- Check that all methods actually ran and did not silently fall back to random search.
- Confirm whether LLM methods used real API calls or fallback random selections.
- Confirm whether optional R and Python backends were available during the run.
- Be clear that the oracle best is the best in the benchmark candidate pool.
- If a sampled candidate pool was used, say that the search was over that pool, not every possible design-grid row.
- If repeat count is small, emphasize trends and uncertainty rather than exact rank order.
- A method can have strong surrogate metrics but weaker optimization performance, or the reverse.
- Selected-condition feature patterns are not causal proof. Treat them as synthesis hypotheses.
